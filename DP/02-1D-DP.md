### House Robber 2
**State:** 
`f(i) = Max amount that can be robbed from starting index upto i.`
    
**Recurrence relation:** 
`f(i) = Math.max(money[i]+f(i-2), f(i-1));`
	Both the state and recurrence relation are same as house robber 1. 
	The only difference is in the range of indices on which we apply it. Since 1st and last house can't be robbed together, we will apply our rec rel on indices 1 to n-1 and 0 to n-2 and take the maximum of the two answers.
  > Note: Based on "break the circle into two lines" pattern
	> Rest of implementation is same as HouseRobber-1.



### Delete and Earn

> **Problem Statement:** You are given an integer array nums. You want to maximize the number of points you get by performing the following operation any number of times:

Pick any nums[i] and delete it to earn nums[i] points. Afterwards, you must delete every element equal to nums[i] - 1 and every element equal to nums[i] + 1.
Return the maximum number of points you can earn by applying the above operation some number of times.

**State:** 
`f(i) = Max amount that can be earned considering values from numbers 1 to i. These are numbers and not array indices.
    
**Rec rel:** 
f(i) = Math.max(f(i-1), points[i] + f(i-2));
    
	Flow:   
    Original array
            ↓
    Group equal numbers
            ↓
    Compute total points for each value
            ↓
    Now adjacent values conflict
            ↓
    This is House Robber
            ↓
    Use the same recurrence

    Note: We need a points array of size max+1 to store sum of each number and the number of times it occurs.
    Before writing DP, transform the problem into one you've already solved. In this case, `**house robber**.`

### Decode Ways
    State: f(i) = No. of ways to decode the suffix string starting from index i.
    Rec rel: If one digit decoding is valid, I do f(i) += f(i+1);
    If two digit decoding is valid, I do f(i) += f(i+2);
    Base case: If i == n return 1;// you have reached end of string in a valid way
    If s.charAt(i)=='0' return 0; // no decoding can start from 0
    Memoization: Store f(i) in DP array to reduce recursive calls
    TC:O(n)


### 3 rules to tackle a DP problem
    What is my state?
    How many unique states exist?
    Are the states contiguous (array) or sparse (HashMap)?

### Coin Change
    State: f(i) = Min number of coins needed to make amount i.
    Rec rel: f(i) = min(1 + f(i - coin)) for all coins available where i-coin>=0
    Here, i denotes the remaining amount.
    Base cases: f(0) == 0; // 0 ways left to make amount 0.
    f(i < 0) = +Infinity; // so that this case doesn't count
    Memoization: f(i) will be stored in a dp array so that overlapping subproblems need not be computed repeatedly.
    TC: O(A.C) where A is the amount and C is the number of coins
